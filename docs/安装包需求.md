# SilentZIP 安装包需求

> 版本：0.3.0 ｜ 更新：2026-11-01

## 一、目标

用户装完 SilentZIP 之后，不需要做任何手动配置，下面三件事自动成立：

    1. 双击 7z / zip / rar / tar / gz / tgz / bz2 / xz / zst / lzh
       → 直接用 SilentZIP 打开

    2. Finder 右键文件
       → 菜单里能看到「用 SilentZIP 打开」「解压到此处（SilentZIP）」

    3. 从任何程序（Finder / DSH / Chrome 下载列表）点「打开方式」
       → 列表里有 SilentZIP

关键约束：不能弹一堆「是否允许 xxx 打开 yyy」的确认窗口。用户最多接受一次授权。

---

## 二、格式结论：用 DMG，不用 PKG

| 对比项 | DMG（拖拽安装） | PKG（安装器） |
|---|---|---|
| 自动注册 | 能做 | 能做 |
| 需要管理员权限 | 不需要 | 需要 |
| 需要安装脚本 | 不需要 | 需要 |
| 用户操作 | 拖进 Applications | 一路下一步 |
| Gatekeeper 提示 | 首次打开时一次 | 安装时一次 |

选 DMG。

理由是实测结论：从 app 进程内部调用 LaunchServices 的默认程序 API，系统不会弹确认窗口。发起者就是 app 自己，系统认得它的身份，直接放行。

之前弹窗的场景是「终端里跑 duti 命令」——那是外部进程替用户改设置，系统每次都要问一遍。只要把注册逻辑放进 app，就不存在这个问题。

---

## 三、DMG 里放什么

    SilentZIP-0.3.0.dmg
    ├── SilentZIP.app                  （拖到 Applications）
    ├── Applications -> /Applications  （软链接，方便拖拽）
    ├── README.txt                     （说明首次启动会自动接管压缩包）
    └── .background/                   （可选，背景图）

不需要安装脚本，不需要授权对话框。

## 四、注册逻辑放在 app 里

### 4.1 触发时机

两处，缺一不可：

    // ① 首次启动：静默注册一遍（不打扰用户）
    func applicationDidFinishLaunching(_ n: Notification) {
        if !UserDefaults.standard.bool(forKey: "didRegisterDefaults") {
            ArchiveTypes.becomeDefault()
            UserDefaults.standard.set(true, forKey: "didRegisterDefaults")
        }
    }

    // ② 菜单里留个手动入口（被别的软件抢走后能抢回来）
    //    SilentZIP → 设为默认压缩工具

### 4.2 已实现的代码

    enum ArchiveTypes {
        static let utis: [String] = [
            "org.7-zip.7-zip-archive",
            "public.zip-archive",
            "com.rarlab.rar-archive",
            "public.tar-archive",
            "org.gnu.gnu-zip-archive",
            "org.gnu.gnu-zip-tar-archive",
            "public.bzip2-archive",
            "org.tukaani.xz-archive",
            "cn.silentstudio.archive.zst",
            "cn.silentstudio.archive.lzh",
            "com.microsoft.cab"
        ]

        static var bundleID: CFString { "cn.silentstudio.silentzip" as CFString }

        @discardableResult
        static func becomeDefault() -> Int {
            var changed = 0
            for u in utis {
                for role: LSRolesMask in [.viewer, .editor, .shell] {
                    _ = LSSetDefaultRoleHandlerForContentType(
                            u as CFString, role, bundleID)
                }
                let cur = LSCopyDefaultRoleHandlerForContentType(
                            u as CFString, .viewer)?
                            .takeRetainedValue() as String? ?? ""
                if cur == "cn.silentstudio.silentzip" { changed += 1 }
            }
            return changed
        }
    }

要点：三个 role 都要设（viewer / editor / shell）。只设 viewer 时，从某些入口（邮件附件、浏览器下载完成后的「打开」）仍然会走旧程序。

### 4.3 右键服务

Info.plist 里声明 NSServices，必须带 NSRequiredContext：

    <key>NSServices</key>
    <array>
      <dict>
        <key>NSMenuItem</key>
        <dict><key>default</key><string>用 SilentZIP 打开</string></dict>
        <key>NSMessage</key><string>openArchive</string>
        <key>NSPortName</key><string>SilentZIP</string>
        <key>NSRequiredContext</key>
        <dict>
          <key>NSApplicationIdentifier</key><string>com.apple.finder</string>
        </dict>
        <key>NSSendFileTypes</key>
        <array>
          <string>public.data</string>
          <string>public.folder</string>
          <!-- 再补各归档 UTI -->
        </array>
      </dict>
    </array>

并在 applicationDidFinishLaunching 里调用：

    NSUpdateDynamicServices()

### 4.4 启用服务状态

macOS 默认把第三方服务设为未勾选。安装包或首次启动需要写一次：

    defaults write pbs NSServicesStatus \
      -dict-add "cn.silentstudio.silentzip - 用 SilentZIP 打开 - openArchive" \
      '{ enabled_context_menu = 1; enabled_services_menu = 1; \
         presentation_modes = { ContextMenu = 1; ServicesMenu = 1; }; }'
    killall pbs

在 app 内可以用 Process 执行，不需要管理员权限（写的是用户级 preferences）。

## 五、如果一定要做成 PKG

无需 PKG。这份仅作为备选记录。

    #!/bin/bash
    # Scripts/postinstall
    set -e

    CONSOLE_USER=$(stat -f "%Su" /dev/console)
    [ "$CONSOLE_USER" = "root" ] && exit 0
    UID_NUM=$(id -u "$CONSOLE_USER")

    for UTI in org.7-zip.7-zip-archive public.zip-archive \
               com.rarlab.rar-archive public.tar-archive \
               org.gnu.gnu-zip-archive org.gnu.gnu-zip-tar-archive \
               public.bzip2-archive org.tukaani.xz-archive \
               cn.silentstudio.archive.zst cn.silentstudio.archive.lzh; do
      launchctl asuser "$UID_NUM" /usr/local/bin/duti \
        -s cn.silentstudio.silentzip "$UTI" all || true
    done

    launchctl asuser "$UID_NUM" /System/Library/CoreServices/pbs -update || true
    exit 0

构建：

    pkgbuild --root payload --identifier cn.silentstudio.silentzip \
             --version 0.3.0 --scripts Scripts SilentZIP.pkg

注意 duti 必须打进 payload，不能假设用户装了 Homebrew。

## 七、已知限制

| 限制 | 说明 | 处理 |
|---|---|---|
| public.iso-image | 被 com.apple.DiskImageMounter 占用 | 不抢，ISO 用系统挂载更合理 |
| 用户手动改过 | 用户自己指定了别的程序 | 只在首次启动注册一次，不反复覆盖 |
| 未签名的 app | 首次打开有「无法验证开发者」 | 需要 Developer ID 证书才能免除 |
| 右键菜单归属 | macOS 13+ 的 NSServices 可能归到「服务 ▸」子菜单 | 已加 NSRequiredContext 对齐 WPS 的结构 |
| Finder 扩展 | 需 Developer ID 签名，ad-hoc 一律被 pluginkit 拒绝 | 拿到证书前不做 |

## 八、卸载

用户把 app 拖进废纸篓后，残留两处，都无害：

    ~/Library/Preferences/com.apple.LaunchServices/
        com.apple.launchservices.secure.plist
        └─ handler 记录（系统自动回落到 Archive Utility，无需清理）

    ~/Library/Preferences/pbs.plist
        └─ NSServicesStatus 里的两条记录（找不到 app 时系统会忽略）

不需要专门的卸载脚本。

## 十、压缩引擎来源（LGPL 合规）

### 10.1 为什么自己编译

7-Zip 官方提供的 macOS 二进制停在 **23.01（2023-06-20）**，
而源码已经更新到 **26.01（2026-04-27）**。
Windows 版已到 26.05。

SilentZIP 内置的 `Contents/Resources/7zz` 由官方源码自行编译，
以消除这个版本差。

### 10.2 精确来源

    源码包    https://www.7-zip.org/a/7z2601-src.7z
    源码版本  26.01
    编译产物  7-Zip (z) 26.01 (arm64) : Copyright (c) 1999-2026 Igor Pavlov
    包内路径  SilentZIP.app/Contents/Resources/7zz
    体积      2,679,536 字节（签名后 2,664,112）

### 10.3 编译命令（可复现）

    cd CPP/7zip/Bundles/Alone2
    make -j8 -f makefile.gcc
    # 产物：CPP/7zip/Bundles/Alone2/_o/7zz

仅使用 Apple 自带 clang，未修改任何源码。

### 10.4 源码提供义务

本软件以二进制形式分发按 GNU LGPL 授权的 7-Zip 组件。
依 LGPL 第 6 条，源码可自以下位置取得：

    官方源码包  https://www.7-zip.org/a/7z2601-src.7z
    官方下载页  https://www.7-zip.org/download.html

如上述地址不可用，可通过 SilentZIP 的关于页面所列联系方式索取，
我们将在合理期限内提供完整源码包。

### 10.5 我们没有修改 7-Zip

**未对 7-Zip 源码作任何改动。** 仅执行官方 makefile 的标准编译流程。
因此不需要分发修改后的源码，只需提供原始源码包即可。

### 10.6 版本适配说明

7-Zip 21.00 之后 `7z l -slt` 的输出字段有变化：

    旧版（17.05）  Attributes = D_ 0rwxr-xr-x     ← 目录靠 D 前缀识别
    新版（21+）    Folder = +                     ← 独立字段，更明确

SilentZIP 的解析器已同时兼容两种格式，见
`ArchiveBackend.parse()` 中的 `Folder` / `Attributes` 分支。

### 10.7 Intel Mac 支持

当前内置引擎为 **arm64 原生**构建。
Intel Mac 会回退到系统已安装的 7z/7zz（如有）。
如需完整支持 Intel，可交叉编译：

    make -j8 -f makefile.gcc CXX="c++ -arch x86_64" CC="cc -arch x86_64"

再与 arm64 版本 `lipo -create` 合并为 universal binary。
